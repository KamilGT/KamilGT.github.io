# KamilGT — сайт-портфолио разработчика

Статический сайт-портфолио: главная страница, каталог проектов и три страницы кейсов.

Технологии: **HTML5, CSS3, vanilla JavaScript**. Сайт не требует сборки, пакетных
зависимостей, Node.js, npm, backend и баз данных — достаточно открыть `index.html`
в браузере или разместить файлы в репозитории GitHub Pages.

Публичный адрес: <https://kamilgt.github.io/>

---

## Структура проекта

```text
my_site/                     (корень репозитория KamilGT.github.io)
├── index.html               Главная страница: первый экран, избранные проекты,
│                            направления, стек, опыт, образование, форматы, контакты
├── projects.html            Каталог проектов с фильтрами по категориям
├── styles.css               Все стили сайта: токены (переменные), компоненты,
│                            адаптивные правила, поддержка prefers-reduced-motion
├── script.js                Vanilla JS: мобильное меню, фильтры каталога,
│                            появление секций, год в подвале
├── favicon.svg              Иконка сайта (SVG)
├── README.md                Этот файл
├── projects/
│   ├── landing-math.html    Кейс: сайт для преподавателя математики
│   ├── ilvera-site.html     Кейс: сайт Ильверы Ситдиковой
│   └── expense-tracker.html Кейс: Expense Tracker
└── assets/
    ├── icons/               Локальные SVG-иконки для блока «Технический стек»
    │   ├── html.svg
    │   ├── css.svg
    │   ├── js.svg
    │   ├── storage.svg
    │   ├── responsive.svg
    │   └── a11y.svg
    └── images/
        ├── og-cover.svg     Исходник обложки для Open Graph
        └── og-cover.png     Обложка для og:image / превью в соцсетях (1200×630)
```

Каталоги `projects/` и `assets/` вложенные: страницы кейсов подключают ресурсы
через `../` (например, `../styles.css`), поэтому при добавлении новых файлов
важно сохранять относительные пути.

## Как запустить локально

Сборка не требуется.

1. Откройте `index.html` двойным щелчком в браузере, **или**
2. в терминале из корня проекта выполните `python3 -m http.server 8000`
   и откройте <http://localhost:8000>. Второй способ ближе к поведению
   GitHub Pages (корректная работа с относительными путями и якорем `#contacts`).

## Как изменить текст

- **Тексты главной страницы** — в `index.html`. Секции помечены комментариями
  (`<!-- Избранные проекты -->`, `<!-- Технический стек -->` и так далее).
- **Тексты каталога** — в `projects.html`.
- **Тексты кейсов** — в файлах каталога `projects/`.
- **Цвета, шрифты, отступы, скругления** — в начале `styles.css`, в блоке
  `:root`. Акцентный цвет задаётся переменной `--accent`.

После правки текста проверьте, что не осталось неподтверждённых сведений:
контакты, метрики, отзывы и ссылки должны быть реальными.

## Как изменить изображения

- **Иконки стека**: замените SVG-файлы в `assets/icons/`. Файлы встроены в
  страницу как `<img>` и уже имеют атрибут `alt=""` (декоративные, потому что
  рядом есть текстовая подпись).
- **Обложка для соцсетей**: обновите `assets/images/og-cover.svg` и
  пересоберите `og-cover.png` в размере 1200×630, затем при необходимости
  поправьте `og:image` в `<head>` страниц.
- **Фотография разработчика**: если появится, добавьте файл в
  `assets/images/` и вставьте `<img>` в первый экран `index.html` с
  заполненным `alt`. Сейчас первый экран намеренно построен на типографике и
  абстрактной технологической панели.
- Без реальных скриншотов проектов карточки используют текстово-графическую
  композицию (класс `.pvis`), а не поддельные скриншоты.

## Как добавить новый проект

1. **Скопируйте страницу кейса.** Возьмите `projects/expense-tracker.html`,
   сохраните под новым именем (например, `projects/new-project.html`) и
   отредактируйте: `<title>`, `meta description`, `og:*`, `<link rel="canonical">>,
   содержимое секций (`Задача`, `Решение`, `Реализованные функции`,
   `Технологии` и остальные — только те, для которых есть подтверждённые данные).
2. **Добавьте карточку в каталог** `projects.html`: скопируйте блок `<article class="pcard">`
   и укажите:
   - `data-category` — ключ фильтра. Существующие ключи: `sites`
     (сайты и лендинги), `apps` (веб-приложения);
   - тег категории, заголовок, описание, список технологий;
   - ссылку на страницу кейса в `href` ссылки «Открыть кейс»;
   - внешнюю ссылку («Открыть сайт») — только если проект опубликован.
3. **Добавьте карточку на главную** в секцию «Избранные проекты» (`index.html`),
   если проект в неё попадает. На главной карточки не имеют `data-category`.
4. **Новая категория фильтра.** Если проекту нужна новая категория, добавьте
   кнопку в `projects.html` в блок `<div class="filters" data-filters>`:
   `<button class="filter-btn" type="button" data-filter="КЛЮЧ" aria-pressed="false">Название</button>`
   и проставьте этот же ключ в `data-category` карточек. Если категория пустая,
   кнопку показывать не нужно. Подсчёт количества карточек и текст счётчика
   (`data-count`) обновляются в `script.js` автоматически.
5. **Композиция карточки.** Если вы хотите другую графическую композицию вместо
   текстовой, отредактируйте блок `.pvis` в карточке (метки, заголовок, знак
   `.pvis__glyph`) — новых файлов для этого не требуется.

## Как опубликовать изменения

Репозиторий должен называться **`KamilGT.github.io`** (или `kamilgt.github.io`) —
тогда GitHub Pages публикует сайт в корень домена `https://kamilgt.github.io/`.

1. Склонируйте репозиторий (или используйте существующий):

   ```bash
   git clone https://github.com/KamilGT/KamilGT.github.io.git
   cd KamilGT.github.io
   ```

2. Скопируйте в корень репозитория содержимое этой папки (`index.html`,
   `projects.html`, `styles.css`, `script.js`, `favicon.svg`, `README.md`,
   каталоги `projects/` и `assets/`). Файл `.DS_Store` копировать не нужно.
3. Зафиксируйте и отправьте изменения:

   ```bash
   git add .
   git commit -m "Обновление сайта-портфолио"
   git push origin main
   ```

4. Через 1–2 минуты GitHub Pages обновит сайт. Проверьте страницы в режиме
   инкогнито, чтобы исключить кэш браузера.

### Какие параметры GitHub Pages проверить

- **Settings → Pages → Build and deployment**: Source = **Deploy from a branch**.
- **Branch**: `main` (или `master`), **folder**: `/ (root)`. Сохранить.
- **Custom domain**: оставить пустым (сайт публикуется по адресу
  `kamilgt.github.io`). Файл `CNAME` не нужен.
- **Enforce HTTPS**: включить.
- **GitHub Actions**: не требуются — сборка сайта не выполняется, публикуются
  готовые файлы. Не добавляйте workflow-файлы для сборки.
- Регистр имени репозитория важен: для адреса в корне домена репозиторий должен
  называться `<username>.github.io`.

## Что нужно добавить перед публикацией

- **Контакты.** Реальные Telegram и e-mail пока не предоставлены, поэтому в
  секции «Контакты» есть только поясняющий текст и ссылка на каталог, а кнопки
  с нерабочими переходами не публикуются. После получения контактов добавьте их
  в секцию `#contacts` на `index.html` и при необходимости вынесите ссылку в
  первый экран (кнопка «Обсудить проект» ведёт на `#contacts`).
- **Ссылки на Expense Tracker.** Публичная демонстрация и репозиторий не
  подтверждены — ссылок на них нет. Если они появятся, добавьте их в карточку в
  `projects.html` и в кейс `projects/expense-tracker.html`.

## Проверки перед публикацией

- Открыть все страницы и убедиться, что внутренние ссылки (навигация, «Открыть
  кейс», возврат в каталог) ведут на существующие файлы.
- Проверить фильтры каталога: «Все проекты», «Сайты и лендинги»,
  «Веб-приложения», включая работу с клавиатуры.
- Проверить мобильное меню на узком экране (кнопка, `Esc`, клик вне меню).
- Убедиться в отсутствии горизонтальной прокрутки на ширине 320–360 px.
- Проверить консоль браузера на ошибки.
- Убедиться, что сайт работает при отключённом JavaScript: контент и ссылки
  доступны, меню отображается в виде обычного списка.

## Принципы контента

Сайт содержит только подтверждённые сведения: реальные проекты с публичными
ссылками, честное описание образования и опыта, без выдуманных клиентов,
отзывов, метрик и контактов. При добавлении новых материалов сохраняйте этот
принцип: если данные не подтверждены — элемент лучше не публиковать.
